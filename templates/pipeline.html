Pipeline

One order for every URL

A check always runs these steps in this order. The score decides which tools open. The page behind the URL is not fetched, and no classifier is trained.

  1. 1InputOne http or https URL, at most 2048 characters.
  2. 2PrepareHost, registrable domain, suffix, port, and a digit-for-letter fold.
  3. 3DetectFired rule weights, capped at 100, and a verdict.
  4. 4Choose pathBelow 21, 21–49, or 50 and above.
  5. 5RetrieveLocal exhibits. One tag at a time on the agentic path.
  6. 6VerifyA sentence stays only when an exhibit tag covers it.
  7. 7ReportVerdict, reasons, withheld sentences, and what to do.

Step 4

The score picks the path

Brand and suffix lists open when the score, a brand token, or a listed suffix calls for them. Verification still runs before the report.

Light · below 21

Short investigation

Read the low-score exhibit. Retrieve any indicator that still fired. A brand token or a listed suffix can still open its registry.

Standard · 21 to 49

One exhibit per indicator

Retrieve each fired indicator by its tag. Do not open both registries unless a token or a listed suffix is present.

Deep · 50 and above

Registries, then each indicator

Open the brand registry and the suffix registry, then retrieve each fired indicator by tag.

Same signal, three stops

Where a mode leaves the pipeline

Rules only

Stops after Detect. It publishes the indicators and a class label. It does not retrieve or verify.

Retrieval only

Runs one word search and attaches that same set to every sentence. It does not check tags.

Agentic chain

Runs the full pipeline. The writer receives only sentences the verifier accepted.
